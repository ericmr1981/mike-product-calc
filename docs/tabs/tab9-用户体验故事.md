# Tab 9: 覆盖天数分析 — 用户体验故事

## 用户故事列表

### US-9-01：输入周销量

**角色**：采购经理

**需求**：我想为各个 SKU 输入预估的周销量，作为覆盖天数计算的基准。

**流程**：

1. 进入"覆盖天数分析"页
2. 系统自动从 `产品出品表` 读取所有 SKU，展示在表格中
3. 每个 SKU 的品类、品名、规格、SKU Key 为只读
4. 在"周销量(份)"列输入预估销量（只填有销量的 SKU）
5. 编辑后自动同步到 session_state

**验收标准**：

- 表格自动加载所有 SKU
- 周销量默认为 0（表示该 SKU 不计入计算）
- 编辑实时同步，无需手动保存
- 数量不可为负数

---

### US-9-02：保存和加载销量数据

**角色**：采购经理

**需求**：本周的销量预估数据我想保存下来，下周可以参考调整。

**流程**：

1. 输入并确认各 SKU 周销量后，点击"💾 保存销量"
2. 下次打开页面，点击"📂 加载已保存销量"
3. 表格恢复到之前保存的数值，无需重新输入

**验收标准**：

- 保存的数据持久化到 `state/coverage_sales.json`
- 加载后表格数据刷新
- 无已保存数据时加载按钮显示提示"未找到已保存的销量数据"
- 保存/加载仅影响周销量列，不影响 SKU 列表

---

### US-9-03：选择仓库计算覆盖天数

**角色**：采购经理

**需求**：我想分别查看 A 仓和 B 仓的覆盖天数，看看是否需要在不同仓库间调拨。

**流程**：

1. 在"选择仓库"多选框中只勾选"A仓库(WH01)"
2. 点击"🔍 计算覆盖天数"
3. 系统加载 A 仓库的库存数据，结合 BOM 和销量计算
4. 结果展示 SKU 覆盖天数和原料覆盖天数两个表格
5. 切回全选仓库重新计算，对比结果

**验收标准**：

- 仓库选择仅出现在 Supabase 连接模式下
- 多选框默认全选
- 仓库标签格式"仓库名(编码)"
- 计算时仅加载选中仓库的库存数据
- 未连接 Supabase 时显示"Supabase 未连接，库存数据为空"

---

### US-9-04：查看覆盖天数的限制原料

**角色**：采购经理

**需求**：某个 SKU 的覆盖天数只有 5 天（紧急状态），我想知道是哪种原料限制了它。

**流程**：

1. 计算完成后，查看 SKU 覆盖天数表格
2. 找到覆盖天数为 5 天、状态为"🔴 紧急"的 SKU
3. "限制原料"列显示了该 SKU 中覆盖天数最少的原料名
4. 在原料覆盖天数表中找到该原料，查看其库存和安全库存详情
5. 根据数据判断是否需要紧急采购

**验收标准**：

- SKU 的覆盖天数取其所有原料中的最小值
- 限制原料明确显示在最右列
- 缺口原料不计入限制原料
- 状态等级清晰可辨：充足(🟢) ≥30 天，一般(🔵) ≥14 天，不足(🟡) ≥7 天，紧急(🔴) <7 天

---

### US-9-05：BOM 缺口导致无法计算

**角色**：运营主管

**需求**：计算覆盖天数时发现一些 SKU 显示状态为"-"，我需要排查原因。

**流程**：

1. 点击"计算覆盖天数"后，部分 SKU 显示状态 "-"
2. 展开"BOM 展开明细"折叠面板
3. 查看该 SKU 的 BOM 展开结果，发现某些原料的 `is_gap` 为 True
4. 在原料覆盖天数表中，缺口原料的 status 显示为 gap_reason
5. 确认该原料在配方中缺失，需要先去"配方管理"补充 BOM 后再来计算

**验收标准**：

- BOM 展开明细面板默认折叠
- 展开后可查看每个 SKU 的 BOM 行数和详细数据
- 缺口原料在覆盖天数中不参与限制计算
- 覆盖矩阵也展示在该面板中（方便 debug）

---

### US-9-06：单位转换影响覆盖天数

**角色**：采购经理

**需求**：我注意到库存数据中"牛奶"的单位是"箱"，但 BOM 中使用的是"升"，覆盖天数计算可能不准确。

**流程**：

1. 点击"计算覆盖天数"
2. 展开"单位转换记录"折叠面板
3. 查看转换记录：`牛奶: 100 箱 → 1200.00 L (×12.0)`
4. 确认转换系数正确：1 箱 = 12 升
5. 覆盖天数结果基于转换后的统一单位计算，结果可靠

**验收标准**：

- 单位转换记录面板默认折叠
- 仅显示实际发生了转换的原料
- 未匹配到目录信息的原料不转换，直接使用原值
- 转换公式：`new_qty = qty × unit_qty`
- 单位转换发生在库存聚合后、覆盖计算前

---

### US-9-07：所有 SKU 销量为零

**角色**：新用户（初次使用）

**需求**：我刚进入页面，还没输入任何销量，想试试计算。

**流程**：

1. 直接点击"计算覆盖天数"
2. 系统提示"请至少输入一个SKU的周销量（大于0）"
3. 用户理解需要先录入销量再计算

**验收标准**：

- 所有 SKU 销量为 0 时显示明确提醒
- 不触发 BOM 展开和计算
- 任何单个 SKU 销量 > 0 即可触发计算

# Tab 4: 产销计划 — 界面结构

## 概览

产销计划 Tab 是一个 4 步顺序流程：销售计划录入 → 生产计划生成 → BOM 展开与原料需求计算 → 成本核算概览。用户必须按从上到下的顺序逐步操作。

## Step 1: 销售计划录入

**位置**: `app.py` 第 1226-1313 行。

**标题**: "Step 1: 销售计划录入"

**子标题**: "录入成品销售预测 — SKU 来自产品毛利表"

**Widgets**:
- **成功消息提示栏**: 从 `_msg_sales_saved` 弹出，显示保存确认。
- **两列布局**:
  - 左列: 下载按钮 "📥 模板(销售)" — 提供 CSV 模板（列: 日期, SKU, 数量）。
  - 右列: 重置按钮 "🔄 重置销售计划和生产计划" — 清空两个计划。
- **文件上传器**: "📤 上传销售计划（CSV / Excel）" — 支持 `.csv` 和 `.xlsx`，自动导入，列名为"日期"、"SKU"、"数量"。
- **导入成功消息**: 从 `_csv_import_msg` 弹出。
- **Data editor**: 动态行数、300px 高度、隐藏索引，三列：
  - "日期": 自由文本输入。
  - "SKU": 基于 `_all_skus`（来自产品毛利表的全部 SKU）的下拉选择。
  - "数量": 数字输入（整数、最小值 0）。
- **保存按钮**: "✅ 保存销售计划" (type=primary) — 校验日期和 SKU，存入 `production_plans["销售计划_当前"]`。

## Step 2: 生产计划

**位置**: 第 1315-1450 行。

**标题**: "🏭 Step 2: 生产计划"

**子标题**: "从销售计划生成后可直接编辑，也可手动录入调整"

**Widgets**:
- **联动仓库选择**: 从 Supabase 最新库存快照获取仓库列表，使用 `get_latest_inventory_rows()`。
- **提前天数输入**: "备货提前天数" (0-30 天, 默认 1)。
- **生成按钮**: "🚀 从销售计划生成生产计划" (type=primary) — 调用 `sales_to_production()` 并触发即时缺货检查。
- **即时缺货预警**: 生成后自动调用 `bom_expand_multi()` + `build_replenishment_plan()` + `summarize_shortage_alert()`，显示缺口摘要。
- **生产计划编辑器**: 动态行数、300px 高度、隐藏索引，三列：
  - "日期": 自由文本。
  - "生产项": 基于 `_production_skus`（从产品配方表/Gelato 和产品出品表/Gelato 提取）的下拉选择。
  - "数量": 数字输入（整数、最小值 0）。
  - key 包含生成版本号 `prod_gen_version` 以强制刷新。
- **保存按钮**: "💾 保存生产计划" (type=primary) — 存入 `production_plans["生产计划_当前"]`。

## Step 3: BOM 展开 — 原料需求计算

**位置**: 第 1452-1645 行。

**标题**: "🔍 Step 3: BOM 展开 — 原料需求计算"

**子标题**: "三级展开：SKU → 主原料/配料 → 原料；支持损耗率、最小采购单位、批次取整、提前期。"

**Widgets**:
- **4 列布局 (参数输入)**:
  - 列 1: 提前期（天），0-90，默认 3。
  - 列 2: 损耗率（%），0-100，默认 0。
  - 列 3: 单价口径选择 — "门店(加价后单价)" 或 "出厂(加价前单价)"。
  - 列 4: 展开按钮 "🔍 展开 BOM" (type=primary)。
- **日期范围过滤**:
  - 开始日期 DateInput。
  - 结束日期 DateInput。
- **展开逻辑**: 从 `production_plans["生产计划_当前"]` 获取行，按日期范围过滤，按 SKU 聚合，调用 `bom_expand_multi()`，结果存入 `_bom_result` session state。
- **补货计划**: 关联到联动仓库，调用 `build_replenishment_plan()`，显示缺口摘要和详细补货表（物料、需求量、可用量、缺口量、建议补货量、单位、紧急程度）。

**3 个内层 Tab**:
1. "📦 原料需求汇总" — 完整 BOM 展开表，包含列：原料名称、层级、采购单位、提前期、计划用量、总需求(含损耗)、建议采购量、单价、采购成本、状态（正常/缺口）、缺口原因、是否半成品。附带 CSV 下载按钮。
2. "⚠️ 缺口预警" — 调用 `gaps_only()` 过滤出缺口行，显示物料、缺口原因、建议采购量、单价、是否半成品。
3. "📊 统计概览" — 4 个指标卡片（原料种类、总采购成本、半成品种类、缺口数量）和按层级统计的聚合表。

## Step 4: 成本核算概览

**位置**: 第 1647-1681 行。

**标题**: "💰 Step 4: 成本核算概览"

**Widgets**:
- **4 个指标卡片**: 原料种类、总原料成本(元)、半成品种类、缺口数。
- **成本构成表**: 按半成品/原料分组，显示原料数、采购量、成本。

## 状态管理

- 所有计划数据存储于 `st.session_state["production_plans"]`，键为 `"销售计划_当前"` 和 `"生产计划_当前"`。
- `_bom_result` 和 `_bom_elapsed` 保存 BOM 展开结果。
- `prod_gen_version` 用于强制 data editor 重渲染。
- `tab4_linkage_warehouse_code` 存储选择的仓库编码。
